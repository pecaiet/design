Pecaiet is the shared look of the Pe caiet apps: **idp** (sign-in and account settings) and **todo** (lists and tasks). Both apps render the same class names with the same tokens, so a change here reaches every app. The look is called **Senin** (Romanian for a clear sky): roomy, soft and calm.

## Colour

- Two themes, three tones each (sidebar, page, cards): light (sky-tinted grey ground, white cards) and dark (deep slate). In the apps, `class="dark"` on `<html>` turns dark on; without it the page is light. The cards here switch with the page's own theme control (`senin-light`, `senin-dark`). Check every new screen in both.
- idp's older names (`card-foreground`, `secondary`, `popover`, `sidebar-accent`, `sidebar-border`, `sidebar-primary` and the rest) are kept as aliases so existing pages keep working; new code uses the main names (`foreground`, `card`, `muted`, `sidebar-hover` and the rest).
- Use the token names, never a raw hex: `background`, `foreground`, `card`, `border`, `input`, `track`, `primary`, `sidebar`, `sidebar-active`, `warning`, `destructive` and the rest.
- Body text is `foreground` on `background` or `card`. Secondary text (dates, counts, descriptions, table headers) is `muted-foreground`.
- `primary` (teal) is the one main action per view and the checked checkbox; text on it is `primary-foreground`, and it darkens to `primary-hover` under the pointer. Links are the text colour with a soft grey underline.
- Notices sit on `primary-soft`, warnings on `warning-soft`, errors on `destructive-soft`. An open dialog dims the page with `overlay`.
- Late dates and counts, and delete actions, are `destructive`.
- `warning` (amber) is for what needs attention soon but isn't wrong yet: due soon, a session about to end, offline. Like `destructive`, it always comes with an icon or words.
- The active sidebar row is a `sidebar-active` pill; its text, icon and count keep the same colours as every other row.
- Every text pair named in a token's note holds 4.5:1 in both themes; `input` holds 3:1 on every surface (card, page, sidebar, muted), `ring` on `card`.

## Type

- Figtree throughout (`--font-sans`), plus the system's monospace (`pc-mono`, `--font-mono`) for IDs, secrets and error codes. Figtree comes in one scale of nine sizes, each with its own line height, and no others: 10/14, 12/16, 14/20, 16/24, 22/28, 28/36, 40/48, and 56/64 and 72/80 for a hero only (`--pc-text-N` with its line `--pc-line-N` in the CSS; a line is named by its own value: `--pc-line-20` is the 20px line of 14px text). The ones in use have names: `pc-title` (22: page, pane and dialog-page titles, a number on a stat), `pc-heading` (16: card, dialog and section titles, the sidebar app name, a large button's words), `pc-body` (14: everything else), `pc-small` (12: dates, counts, labels, hints, keys, tooltips, code), `pc-tiny` (10: letters in a 20px app mark or a 24px avatar, a small badge's count). In the apps they are the Tailwind utilities `text-pc-title`, `text-pc-heading`, `text-pc-body`, `text-pc-small`, `text-pc-tiny`, plus `text-pc-28`, `text-pc-40`, `text-pc-56` and `text-pc-72`; Tailwind's own sizes (`text-sm`, `text-lg`, …) are not used.
- The apps load fonts only from their own origin (idp's Content Security Policy), so Figtree is self-hosted as woff2 files.

## Shape and density

- One row height, `pc-row` (32px; 40px on phones, where fields take 16px text), for every row and control: sidebar, menu, search and table rows, calendar days, buttons, inputs, selects.
- Every size comes from a token, and every kind of size has one short scale (tokens.json, a section each on this page):
  - Spacing (`pc-space-*`): 2, 4, 6, 8, 10, 12, 16, 24, 32, 48.
  - Text (`pc-text-*`): 10, 12, 14, 16, 22, 28, 40; 56 and 72 for a hero only.
  - Line heights (`pc-line-*`), named by their own value, one for each text size: 10/14, 12/16, 14/20, 16/24, 22/28, 28/36, 40/48; 56/64 and 72/80 for a hero.
  - Sizes (`pc-size-*`), fixed squares: 12 (the smallest marks), 16 (icons beside words, checkboxes), 20 (an icon on its own, badges, handles), 24, 32 and 48 (avatars; the play button; the search window's field).
  - Heights of controls (`pc-row-*`): `pc-row-xs` 24 (chips in a field), `pc-row-sm` 28 (small), `pc-row` 32, `pc-row-lg` 40 (large); on phones each is worked out from `pc-row-touch` (40): 32, 36, 40, 48.
  - Every size in the CSS is a token or a sum of tokens. Two plain values remain, because CSS can't take a token there: the phone breakpoint (48rem, in media queries) and the huge inner shadow that hides a browser's autofill colour.
  - Widths (`pc-width-*`): 160, 256 (the sidebar, menus, tooltips), 320, 400, 560, 960. Heights of what scrolls (`pc-height-*`): a list 360, the settings window 640, a phone sheet 85% of the screen.
  - Corners (`pc-radius-*`): 2, 5, 10, 14 and round.
  - Edges (`pc-border`, `pc-border-2`): 1, and 2 for the tab underline, a quote's line and rings around avatars and swatches.
  - Bars and dots (`pc-bar-*`, `pc-dot-*`): bars 2, 4, 6; dots 8, 12.
  - Weights (`pc-weight-*`): 400, 500, 600, 700. Letter spacing (`pc-tracking-*`): −0.01em from 22 up, −0.02em for a hero.
  - Fading and mixing one colour into another (`pc-opacity-*`): 12% faint (edges round photos, soft teal), 50% half (what can't be used, a quiet line, the segmented hover).
  - Layers (`pc-layer-*`), bottom to top: raised, tooltip, menu, drawer, sheet (a phone sheet and the dimmed page behind it), toast, skip link.
  - Motion (`pc-motion`): 120ms for everything that moves (Motion, below).
- Corners: `pc-radius-xs` (2px) for focus rings round links and the tab underline, `pc-radius-sm` (5px) for checkboxes and key caps, `pc-radius` (10px) for every row and control (tabs and a rating's stars take `pc-radius-sm`), `pc-radius-lg` (14px) for panels (cards, menus, dialogs, popovers). Avatars, badges, chips and radios are round. Inside a padded container the inner corner is the outer one minus the gap: menus keep 4px around 10px rows (14 = 10 + 4).
- Shadows: `pc-raise` for cards, the raised pill (a toolbar tool under the pointer, the chosen segment), the slider's handle and a switch's knob; `pc-raise-lg` for what opens over the page (menus, dialogs, popovers, drawers, toasts, tooltips) and a video's play button. The active sidebar row is a flat pill: its fill alone marks it.

## Motion

- One speed and one curve: `pc-motion` (120ms) for everything that changes, appears, leaves or travels, with Ease out (`--pc-motion-ease`). Longer times are multiples of it: a tooltip's wait ×3 (360ms), one spinner turn ×7 (0.84s), unknown progress ×12 (1.44s), the skeleton's pulse ×13 (1.56s).
- Changes: hover and focus colours fade, ticks and dots fade in, arrows turn (accordion, tree, Select), an icon swapped in a button (a copy's tick, the spinner at work) fades in.
- Then three kinds of motion, the same everywhere and never two at once (nothing fades while it moves):
  - Fade, something appears in place: menus, popovers, tooltips (after 360ms), dialogs, tab panels, carousel slides, chips added or removed and content that takes a skeleton's place fade in and out where they are.
  - Grow, something takes room or gives it back: toasts and field errors grow in whenever they appear; a row or alert the person just added (`Pecaiet.enter(el)`, or a Turbo stream that adds it) grows in; accordion answers and tree branches grow open and shrink closed; a removed row, alert or toast shrinks out. Each fades while it grows, in one motion, so what's around it glides instead of jumping. Content that's only drawn again (a Turbo frame, a React update) shows at once, never row by row. Table rows can't grow: they fade.
  - Slide, something comes from an edge or travels: the drawer, the sidebar and its phone sheet, the sheets on phones and the skip link slide in from their edge; the switch's knob, the segmented pill, the tab line and a progress bar slide to their new place.
- Loading: the spinner turns, the skeleton pulses, unknown progress slides. Pages crossfade (Chrome, Edge, Safari). Jumps within a page scroll smoothly. Numbers, the stepper's number and a pressed button don't move.
- Settings has a Motion card: On · Off. Off (`data-motion="off"` on `<html>`, remembered in the motion cookie) makes everything instant; the spinner still turns, slowly. Until someone chooses, a device that asks for less motion gets Off.
- `pecaiet.css` plays everything the browser can on its own. `pecaiet.js`, next to it in the design repo, plays the rest: closings in every browser, everything that grows (`Pecaiet.enter`, `Pecaiet.leave`), the tab line, the theme's crossfade (`Pecaiet.setTheme`) and the Motion setting (`Pecaiet.setMotion`). Without it, those just happen at once. The Motion card shows them all.

## Components

- `components/bundle.css` holds every class both apps use. Each component has a card here showing its states in light and dark, and a guideline under it. The code the apps import is `pecaiet.css` in github.com/pecaiet/design.
- Every class and every variable of our own starts with `pc-` (`.pc-btn`, `.pc-sidebar-item`, `--pc-row`, `--pc-raise`), so nothing an app defines can clash with them. Two families keep standard names: the colour tokens (shadcn's: `primary`, `muted-foreground`, …) and the fonts (Tailwind's: `--font-sans`, `--font-mono`). States are attributes, never classes.
- The cards follow component.gallery's list of component types (it collects them from 90+ public design systems): its 60, with its names, in its order. A card with no preview is one not designed yet. Our own pieces that aren't on that list come after the 60: Code, Focus, Page header, Sidebar item, Sidebar account, App switcher, Input group.

- Not needed for now, kept as names only (each card says so): Hero, Rich text editor.
- Pages, last: Email, Error page, Settings modal (a big window with its own nav, over the page you are on; full screen on phones), Sign in. Whole pages as the apps build them, marked as pages: examples to follow, not components to mount.
- The current page's sidebar item carries `aria-current="page"`. Each app decides which one that is; the CSS only styles the attribute.
- Hover, keyboard focus and disabled states are built into the classes, the same way everywhere:
  - Hover: every clickable row and ghost or outline control takes a fill (`accent` on surfaces, `sidebar-hover` in the sidebar).
  - Focus, as on claude.ai. Controls (buttons, fields, checkboxes, links) use `pc-focus`: their outer 1px turns the page colour (bordered controls turn their border that colour), then a 1px blue `ring` line on the edge and a soft glow in a darker blue. Rows (sidebar, menu, search, calendar days, table rows) use `pc-focus-inset`: the ring inside the row's own edge, only the glow outside. A transparent outline stays underneath for Windows high-contrast mode. Blue is used for focus only, so it shows on teal buttons and ticked boxes too. Rows also take their hover fill. Sidebar rows sit 2px apart. Menu and search rows sit 4px apart. Borderless inline fields (the search field) show only the caret.
  - Disabled: half strength and a not-allowed pointer, fields included. Buttons instead keep their own shape, in grey: a button with a box turns one flat grey box, a ghost button grey words with no box.
  - Choices from a list use the Select (our own list), never the browser's dropdown. Every menu that pops up (pickers, the account menu, the app switcher, row actions) is a dropdown on desktop and a sheet at the bottom of the screen on phones.
  - Divider lines (menus, card footers, the search dialog, table headers) run edge to edge, the same everywhere.
  - Panels (cards, dialogs, popovers) have 16px inside.
  - Scrollbars are thin and muted (`muted-foreground` at 40%, no track), drawn by the browser on every scroll area and the page itself, so each system keeps its own behaviour (macOS hides them until you scroll).

## Iconography

- Phosphor icons (phosphoricons.com), regular weight, drawn in `currentColor`: 16px beside text of any size; 12px for the smallest marks. todo uses `@phosphor-icons/react`; idp inlines the same SVGs from `@phosphor-icons/core`. Icons sit in `muted-foreground`, except in sidebar rows, where they take the text colour.
- No emoji in the interface.

## Copy

- Sentence case everywhere.
- Buttons say what happens: "Save email", "Sign out", "Delete account".
- Speak to the person as "you"; name devices the way people know them: "Chrome on macOS", "2 hours ago".
